# MIQA — latest standing photo delivery requirements

User update: 2026-11-03. Apply alongside MIQA-PHOTO-WORKFLOW.md when available; this newer square-format instruction supersedes previous portrait delivery defaults.

- Every new supplied watch requires THREE distinct photographs: main product hero, natural wrist-worn view, detail close-up. A single reference does not reduce the required count. Only an explicit scope change overrides this.
- ALL THREE FINAL WEBSITE IMAGES MUST BE SQUARE, aspect ratio 1:1, equal width and height. Prefer consistent square dimensions within a set. Plan new generated compositions for square framing from the start.
- Do not stretch the watch, distort hands/bracelet/wrist anatomy, or crop away essential product parts to force a square. Preserve genuine photographic proportions; if adapting existing work, use careful safe framing/background/canvas treatment rather than silent stretching or arbitrary downsampling.
- Website file sizes must be as small as genuinely possible WITHOUT QUALITY LOSS. Compare lossless WebP with optimized full-color PNG; deliver the smaller pixel-verified lossless result. High lossy quality, even 100, is not a lossless guarantee.
- Keep canonical masters. Verify decoded RGBA equality against each finalized square master and preserve intended ICC/orientation. Do not palette-quantize, blur, sacrifice detail, silently reduce resolution or fake native 4K to hit a size cap. No guaranteed KB target before testing real assets.
- Record square dimensions, actual bytes/savings and hashes; inspect product/skin/glass/metal/Bengali label at native and phone display sizes.
- Confirmed Bengali butterfly-lock label belongs only on main; wrist/detail stay free of that extra writing. Do not invent hidden-clasp evidence.
- This message sets the standing format/compression requirement; do not claim already-delivered portrait files have become square without actually creating and verifying revised files.
